# Space Dog Racing — asset list

**The contract between the code and the art.** Every image the game will look for: where it goes, how big it is, what it may weigh, and a prompt you can paste straight into an image model with this planet’s vibe and its two accent hues already in it.

Generated by `npm run asset-list` from `packages/web/scripts/assets.ts`, which reads the planets and the event deck out of the engine and the hotspot positions out of `packages/web/src/lib/hotspots.ts`. Edit that script, not this file — a hand edit here is gone the next time it runs.

---

## How dropping art in works

1. Generate the image to the size in its entry and save it as **WebP** at exactly the path given, under `packages/web/src/assets/`.
2. That is all. Vite picks it up through a glob, fingerprints it into `dist/assets/`, and the game uses it on the next build. No code change, no import to add, no list to update.
3. **Placeholders are `.svg`, finished art is `.webp`.** `npm run placeholders` writes a labelled stand-in for every entry below. The resolver in `src/lib/assets.ts` prefers the `.webp`, so the moment yours lands it takes over — and every component that is still showing an `.svg` stamps PLACEHOLDER on itself, which disappears by itself when you replace it. Delete the `.svg` afterwards or leave it; nothing changes either way.
4. Nothing is ever missing enough to break a screen. A hub with no backdrop still paints its own chrome, a dog with no portrait shows a labelled slot, an event with no card shows a hatched panel. A blank screen is a bug, not a missing file.

Everything is loaded lazily and per planet, so the whole set is never fetched at once. First paint is the app itself (~300 kB of JS and CSS, ~100 kB gzipped) plus the one backdrop for the planet you are standing on. A weekend costs one backdrop, one ground and one surface.

**149 files, about 11.4 MB if you hit the targets and 20.7 MB if every one lands on its cap.** That is the whole library, not a download: no player ever fetches all of it, because backdrops, ground and surfaces are per planet and a season visits thirteen of eighteen.

Two levers if that total wants to come down:

- **Tier 1 alone is 38 files and about 3.2 MB**, and it is most of the difference between "unfinished" and "finished": the 18 hub backdrops and the 20 dog layers. Generate that first, play it, and decide about the rest afterwards.
- **The race-view ground and surfaces (36 files, ~4.2 MB) can share.** Nothing in the code requires eighteen of each: copy one set across a family of planets that look alike — ice, desert, industrial, organic, urban, void — and six of each covers all eighteen for about 1.4 MB. Same for a shared surface tile per family.

Every entry says both a **target** (what a well-compressed export of that style should come to) and a **cap** (over this, re-export at a lower quality — the site is meant to feel instant on a phone). WebP quality 72–78 hits the targets for flat cel-shaded painting; transparent layers want 85 or the outlines go crunchy.

## The locked style

Every prompt below already carries this, so you do not have to paste it separately. It is here so the whole set can be regenerated consistently if the look moves.

```text
1990s PC-game digital painting, chunky black outlines, flat cel shading, saturated grime —
Gazillionaire's pastel cartooning crossed with Death Rally's soot and neon, everything
slightly held together with tape
```

Base palette (GDD §16): charcoal `#1B1A22`, rust `#6B3A22`, acid green `#9BE84B`, hazard yellow `#F4C542`, hot pink `#F04E98`, cyan `#3FD6E0`. Each planet overrides two accents, and those are already substituted into its prompts below — the same two hues the game reads out of `Planet.accents` to tint that planet’s chrome, so the art and the UI agree without anyone syncing them.

**Seeds.** Every entry carries a hundred-wide seed band of its own. Re-roll inside the band and the family stays consistent; the bands never overlap, so two planets can never accidentally converge on the same image.

## Adding a nineteenth planet

One data row in `packages/engine/src/content/planets.ts` — name, vibe, track, food band, special, and its two `accents` — plus three images:

```text
packages/web/src/assets/planets/<id>/backdrop.webp   1920×1080
packages/web/src/assets/planets/<id>/ground.webp     2048×2048
packages/web/src/assets/planets/<id>/surface.webp    512×512, seamless
```

No code change. Hotspots fall back to the `arc` arrangement if the planet has no row in `lib/hotspots.ts`; add one to pick a different composition. The track shape comes from the planet’s own distance and bends, its chrome from its accents, and its rules from its `special` block.
